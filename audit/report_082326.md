# Live Launch Loading Audit

**Site:** `https://angelawallace.net/`  
**Repository:** `portfolio-clean`  
**Audit date:** August 23, 2026  
**Repair branch:** `fix/live-loading-audit-082326`

## Executive summary

The root-level shared folder was confirmed as the primary dependency preventing the live site from completing its intended load sequence.

The portfolio pages referenced `/shared/css/*` and `/shared/js/*`, but those files existed only in the sibling `/Users/awd/Development/shared` repository. GitHub Pages published `portfolio-clean` without that sibling repository, so the production shared URLs returned 404 responses. Because the page entry modules statically imported missing shared JavaScript modules, their initialization stopped before page-load classes, theme behavior, observers, slides, and icons could initialize.

This branch vendors the committed shared runtime files into `portfolio-clean/shared`, which is the path already expected by the site. It also corrects the nested-page chart data request that caused a separate JSON parsing failure.

## Production findings before repair

### Shared assets were missing

The following representative production URLs returned the GitHub Pages 404 page:

- `https://angelawallace.net/shared/css/global-tokens.css`
- `https://angelawallace.net/shared/js/base.js`

All four shared stylesheets were present as stylesheet links in the live DOM but contained zero CSS rules:

- `shared/css/global-tokens.css`
- `shared/css/global-components.css`
- `shared/css/utilities.css`
- `shared/css/motion.css`

### Homepage initialization was blocked

`js/site.js` imports `shared/js/theme.js` and `shared/js/page-observers.js`. The missing modules prevented the entry module from executing, including `initPageLoad()`.

Observed live state:

- Body classes remained `long-page intro-layout` instead of gaining `is-loaded fade-in`.
- Intro copy computed to `opacity: 0`.
- Laptop mockup computed to `opacity: 0`.
- Phone mockup computed to `opacity: 0`.
- Work data loaded independently, but the intended complete page reveal and shared behavior did not.

### Nested case-study data request failed independently

`js/chart.js` fetched `js/data.json` relative to the current document URL. On nested case-study routes this resolved to a nonexistent nested path, returned an HTML 404 page, and produced:

`Unexpected token '<', "<!DOCTYPE "... is not valid JSON`

## Repairs in this branch

### 1. Added the shared runtime to the deployed repository

Added the following root-level runtime files under `portfolio-clean/shared`:

- `shared/css/global-components.css`
- `shared/css/global-tokens.css`
- `shared/css/motion.css`
- `shared/css/utilities.css`
- `shared/js/base.js`
- `shared/js/createIcon.js`
- `shared/js/icons.js`
- `shared/js/interactions.js`
- `shared/js/page-observers.js`
- `shared/js/pattern-slides.js`
- `shared/js/theme.js`

The initial files were sourced from committed revision `f640e0f` of the sibling `shared` repository. Uncommitted files and `.DS_Store` files in that repository were not copied wholesale; the motion corrections documented below were applied directly and reviewed on this repair branch.

### 2. Made chart data resolution module-relative

Changed the chart data URL to resolve from `import.meta.url` and added an HTTP status check. The request now resolves to `/js/data.json` regardless of which page imports the module.

### 3. Corrected the Payments page title

Changed the copied Data Sharing title to `AWD Case Study - Payments Experience`.

### 4. Repaired internal anchor navigation and back-to-top controls

Added document-level smooth scrolling as a CSS fallback and a shared JavaScript anchor handler that:

- Animates same-page hash links with a consistent eased duration.
- Preserves URL hashes and browser history.
- Honors target `scroll-margin-top` values.
- Allows wheel and touch input to interrupt an active animation.
- Disables animation when the user prefers reduced motion.

The page-load transform was also removed from `body`. Even at `translateY(0)`, that transform created a containing block for fixed descendants and caused the second-tier back-to-top control to be positioned relative to the full document instead of the viewport. Page entry and motion asset URLs now use cache-busting versions so deployed browsers load the repaired behavior immediately.

### 5. Completed a responsive layout and interaction pass

- Reworked both lightbox implementations so images fit within dynamic mobile viewport bounds, close controls remain visible inside safe areas, page scrolling locks only while open, and focus returns to the originating image link. Touch devices use a stable fit-to-screen view; desktop case-study images retain click-to-zoom behavior.
- Removed the featured-project hero's fixed viewport-derived height and minimum height. The hero now derives its height from its content while still accounting for the decorative extrusion.
- Made the homepage global navigation sticky at responsive breakpoints and corrected the header markup so sticky positioning is not constrained by a short wrapper.
- Extracted the Payments shadow into the reusable `.image-treatment--soft-shadow` class and applied the same treatment to the About profile image.
- Replaced the third Services category with `DELIVERY` and the supplied implementation, validation, QA, workflow, and production-alignment capabilities.
- Hid the redundant tagline beneath the Designing with AI title eyebrow.
